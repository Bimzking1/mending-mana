# Handoff

The UI is built. The data and pipeline work is not. Below is a prompt you can paste into
another AI tool (Cursor, Claude Code, Copilot, Gemini, whatever) to continue. Give it the
repository as context, then paste **Prompt A** first. Prompts B and C come later, one at
a time — do not paste all three at once.

---

## Prompt A — comparison engine and data quality

```text
You are continuing an existing React + TypeScript + Vite + Tailwind project called
"Mending mana?". It converts the price of something a person is about to buy into
recognisable Indonesian products that cost the same amount.

The UI layer is finished and is NOT yours to redesign. Do not change:
- any file in src/components/ or src/screens/
- src/index.css, tailwind.config.ts, index.html
- the visual design, the copy, the colour tokens, or the layout

Your scope is data and logic only. Read first, in this order:
README.md, DATA-SCHEMA.md, src/types/index.ts, src/lib/compare.ts, scripts/seed.mjs.

Task 1 — improve the selection engine in src/lib/compare.ts.
Keep the exported signature exactly as it is:
  selectComparisons(items, query, limit) => Comparison[]
It must stay a pure function: same input, same output, no fetching, no randomness, no
Date.now(). The UI imports nothing else from this file except MAX_RESULTS and
cheapestPrice.

Make the selection better on these axes, in this order:
1. Diversity — a result set must not be five drinks. Cap items per category and per
   brand (the current cap is 2 per category, 1 per brand; tune it, don't remove it).
2. Quantity appeal — quantities that land between roughly 2 and 30 are the most
   striking. A result of "~1×" is weak, "~4.312×" is noise. Score accordingly.
3. Recognizability — the recognizability field (1–5) should matter.
4. Category relevance — when query.category is set, lift that category but never
   silence the others; the cross-category surprise is the point of the product.
5. Determinism and speed — it runs on every result render over ~200 records.

Add unit tests (vitest; add it as a devDependency) covering at least:
budget below the cheapest item returns []; budget 500000 returns between 6 and 8 items
spanning at least 4 distinct categories; a selected category appears in the first two
results; the same input twice returns identical output.

Task 2 — grow the reference data.
The data lives in src/data/latest.json and is generated by scripts/seed.mjs. Extend the
TABLE in that script toward 200–300 items, keeping the existing rules from
DATA-SCHEMA.md: specific products with a real brand (never "Coffee" or "Shirt"), integer
rupiah, a displayUnit that reads naturally after a price ("/ gelas", "/ tiket"), an
honest recognizability score, and isSample: true on every record whose price you have
not verified against a live source. Do not invent sourceUrl domains that don't exist.
Spread items across all nine categories and across price bands from about Rp5.000 to
Rp15.000.000, so both small and large budgets produce good results.

Finish by running: npm run build. It must pass with zero TypeScript errors. Report what
you changed and anything you deliberately left alone.
```

## Prompt B — the scraper (only after Prompt A is merged)

```text
Continue the "Mending mana?" project. Read SCRAPER.md and DATA-SCHEMA.md in full before
writing anything; SCRAPER.md is the specification and it is authoritative.

Implement the pipeline in scraper/, one stage at a time, in this order:
collect.ts → categorize.ts → diff.ts → merge.ts → export.ts

normalize.ts, validate.ts and deduplicate.ts already work — use them, don't rewrite them.
The stage files currently print "not implemented" and exit 1; replace that only when the
stage genuinely works. Never fake a stage.

Hard rules:
- No paid service, no API key, no headless browser unless there is no alternative.
- Respect robots.txt and rate limits; one request at a time with a delay.
- A scraper run writes a NEW timestamped file in collections/ and never overwrites one.
- Only merge.ts may touch src/data/latest.json, and only from an approved diff.
- A price change over ±40% is flagged for review, not applied silently.
- Records that fail validation are logged with a reason, never dropped in silence.
- isSample stays true unless the price was confirmed against a live sourceUrl.

Then implement two real source adapters under scraper/sources/ as reference
implementations — pick sources with stable, publicly listed prices — and document them in
SCRAPER.md § "Adding a new source".

Do not touch src/components/, src/screens/, or any styling file.
Finish with npm run build passing.
```

## Prompt C — remaining product features

```text
Continue the "Mending mana?" project. The visual design is settled; match the existing
tokens and components rather than introducing new patterns. Read src/index.css and
src/components/ui/ first.

Implement, in this order, each as a separate change:
1. URL state. Encode the query (item, budget, category) in the URL so a result can be
   linked and reloaded. Use the History API; do not add a router dependency for this.
2. Share image. src/lib/share.ts already builds the text version. Add a rendered image
   of the result (canvas or SVG → PNG) sized for Instagram Stories, using the same
   tokens. Wire it to a button beside "Salin hasil" and use navigator.share when
   available, download otherwise.
3. Region switch. Every record already has a region field. Add a quiet switch
   (Jakarta / Bandung / Surabaya) and filter on it, with a sensible fallback when a
   region has too few records.

Keep the bundle small: no animation library, no state library, no UI kit. Everything
must work on a 320px-wide screen with one hand, and respect prefers-reduced-motion.
Finish with npm run build passing.
```

## Boundaries that matter

If an AI touches these, the design breaks:

| Do not change | Why |
| --- | --- |
| `src/index.css` token blocks | Every colour in the app resolves from them, in both themes. |
| `tailwind.config.ts` scales | Type, radius and shadow steps are deliberate, not defaults. |
| `formatRupiah` / `formatQuantity` | Single source of truth for every number on screen. |
| The `~` prefix on quantities | Prices vary by city and promo; the app must not claim precision. |
| Indonesian copy | It is written to sound spoken, not translated. |
| `selectComparisons` signature | Four screens depend on it. |

And the product line that is easy to cross: **the app never tells anyone what to buy.**
No "too expensive", no "you should save", no score, no judgement. It shows what the same
money is, and stops.
